# 人工布局调整与流水线交接方案

状态：交互与接口方案；人工编辑页面及下述接口尚未实现。

## 1. 插入位置与目标

流水线顺序：

```text
自动修复：Shield 层中心对齐、箭头共享底部对齐等
  → 人工布局调整
  → 操作员确认布局
  → 按最新 SVG 执行 Shield punch-out 和方向箭头拆分
  → 检查每个方向的叠加效果
  → 确认最终输出
```

人工环节解决自动修复后的局部文字重叠、文字大小或宽度、整体组合偏移、出界，以及图层遮挡。内部 path ID 保持稳定。操作员主要通过形状、缩略图和选中状态辨认对象，不需要理解 ID。

## 2. 建议实现方式

使用一个固定首屏布局的 Web 页面和 Python 后端。前端直接操作带稳定 ID 的内联 SVG，负责命中选择、高亮、快捷键、即时预览和撤销状态；后端负责 SVG 的安全修改、持久化、正式渲染、punch-out 调用和输出文件。具体 Web 框架可在接入时选择；接口不依赖特定框架。

普通编辑无需调用多模态模型。每次移动的数值由操作员输入、方向键或鼠标拖动产生，并由程序换算到 SVG 坐标。后端必须是最终 SVG 的权威来源；浏览器的即时预览与后端正式渲染应在确认前对照一次。

## 3. 流水线传入内容

每个待编辑任务提供：

| 字段 | 必需 | 含义 |
|---|---|---|
| `task_id` | 是 | 本次任务的唯一标识 |
| `reference_png` | 是 | 目标布局图 |
| `current_svg` | 是 | 自动修复结束、进入人工环节时的完整 SVG |
| `output_dir` | 是 | 本任务独立的输出目录 |
| `arrow_shield_map` | 是 | 每个方向的箭头 path ID 与相关 Shield path ID 的对应关系 |
| `shield_groups` | 否 | Shield 外框各层的建议组合；有则显示为可检查的选择预设 |
| `arrow_groups` | 否 | 多方向箭头的建议组合；有则显示为选择预设 |
| `font_options` | 否 | 可选择的字体名称；缺省时仍显示当前 SVG 字体名称 |

建议传递结构，具体路径由集成方提供：

```json
{
  "task_id": "sign-001",
  "reference_png": "/task/sign-001/reference.png",
  "current_svg": "/task/sign-001/current.svg",
  "output_dir": "/task/sign-001/human-review",
  "arrow_shield_map": [
    {
      "direction_id": "up",
      "arrow_path_ids": ["path_021"],
      "shield_path_ids": ["path_031", "path_032", "path_033"],
      "shield_text_ids": ["text_008"]
    }
  ],
  "shield_groups": [
    {"group_id": "shield-up-frame", "path_ids": ["path_031", "path_032", "path_033"]}
  ],
  "arrow_groups": [
    {"group_id": "shared-arrow", "path_ids": ["path_021", "path_022", "path_023"]}
  ],
  "font_options": ["Noto Sans CJK JP", "Arial"]
}
```

`direction_id` 只需在一个任务内唯一，不限定为 `up`、`left`、`right` 三种；有多少方向就输出多少个方向文件。`shield_text_ids` 独立于 Shield 框路径，便于单独调整数字或文字。映射来自已有的方向箭头／Shield 关联数据，不要求预先建立完整语义标签体系。未提供的建议组合不应自动臆造为确定事实，操作员可多选并保存本次编辑的临时组合。

入口校验：SVG 必须可解析；映射引用的 ID 必须存在且唯一；参考 PNG 与 SVG 的画布坐标应能直接对应。若尺寸或裁切不同，入口必须另给明确的坐标映射，不能靠页面自行猜测。编辑期间不重新编号；导出时验证全部入口 ID 仍可追踪。图层顺序和文字内容可以修改，但不能因此更换既有 ID。

## 4. 首屏布局与选择

首屏显示参考 PNG、当前正常着色的 SVG、结构轮廓视图和紧凑操作区。三个视图使用相同的画布坐标、缩放与平移。参考图叠加所选元素当前轮廓的半透明投影，帮助判断位移方向；这个投影表示当前 SVG 位置，不表示系统识别了参考图里的目标轮廓。

正常 SVG 与结构视图都能选择对象。结构视图给每个 path 独立的轮廓颜色、淡化未选对象，且可点到被遮挡元素。重叠处弹出候选元素缩略图供选择。两处选择状态同步；再次点击已选对象可取消。右侧显示所选对象数量、缩略预览和可展开的原始 ID。path ID 默认不占据画布空间。

默认选择规则：

- 点击任一方向箭头时，默认选中本图所有方向的箭头及其关联 Shield 框，一起移动整个组合。程序从 `arrow_shield_map` 汇总这些成员；操作员可展开并取消某些成员，或只选一支箭头。`arrow_groups` 可作为流水线额外提供的组合预设。
- 点击 Shield 框时，选中该 Shield 框的各层，不自动选中内部数字。若没有对应预设，先选当前层，再由操作员多选其余层并保存临时组合。
- 点击文字或数字时，只选中该文字元素。
- 任意多个已选元素可作为一个集合共同移动；这是本次操作的选择集合，不强制改变 SVG 的 `<g>` 结构。

上述“箭头及 Shield”规则依赖传入的明确映射。若任一方向缺映射，界面显示“关联未提供”，允许人工多选，而不能静默选错。

## 5. 编辑操作与反馈

| 操作 | 规则 |
|---|---|
| 平移 | 方向按钮、键盘方向键、拖动轮廓；多选成员使用同一位移，保持相对位置 |
| 步长 | 默认 1 SVG 画布单位；提供可输入数值及小／中／大快捷档 |
| 方向约束 | 可锁定水平或垂直方向，便于两个 Shield 同时调高低 |
| 文本 | 编辑内容、字号、水平宽度、位置；水平宽度调整保持高度不变 |
| 字体 | 显示当前 `font-family`；允许选择或输入字体名称，并即时预览 |
| 图层 | 上移一层、下移一层、置于最前、置于最后；结构视图同时显示结果 |
| 历史 | 每次操作可撤销、重做；可恢复到人工环节入口状态 |

图层调整由后端按实际 SVG 树处理。如果文字与遮挡面板不属于同一父组，不能假装组内上移就能覆盖它；应给出明确的“需移动所属组／调整跨组顺序”操作或提示。背景和画布等非编辑对象默认锁定，但可在高级视图检查。

画布边界必须有明显反馈：选中对象越界、箭头接触边界或文字超出时，在正常预览中标红并列出相关对象。参考图与当前 SVG 可切换为半透明叠加比较。重叠提示只针对文字与非预期对象等可疑情况；Shield 层以及共享箭杆的设计性重叠不应被一律视为错误。

文字可能是 `<text>`，也可能被转成 path。若为 path，位置和图层仍可调整，但内容、字号、字体名称不可按文字属性编辑；界面需把这些控件置灰并说明原因。预览时使用同一套可用字体；最终确认前必须查看后端正式渲染图。

## 6. 确认、punch-out 与输出

“完成布局”保存一个不可被后续预览覆盖的候选 SVG，并用它调用当前的 punch-out 实现。punch-out 适配层接收候选 SVG、`arrow_shield_map` 和输出目录；现有函数无论是读取完整 SVG 还是读取已提取的路径，都由适配层转换，不将该实现细节暴露给页面。

每次再次点击“完成布局”都根据最新候选 SVG 重新生成方向文件。布局、文字或图层在此后任何修改，已有方向结果立即标记为过期；只有重新生成并检查后才可最终确认。

输出建议：

```text
output_dir/
  original.svg                  # 人工环节入口 SVG 的完整副本
  edited.svg                    # 操作员确认的完整 SVG
  edited.png                    # 后端正式渲染
  directions/
    <direction_id>.svg          # 每个方向独立的箭头／Shield punch-out 结果
  previews/
    <direction_id>.png          # 独立结果的预览
    <direction_id>-overlay.png  # 与完整 SVG 叠加后的预览
  edits.json                    # 编辑摘要、原始及最终文件的校验信息
```

方向结果区域放在首屏下方，包含每个独立 SVG 的预览和叠加预览。最后的“确认最终输出”只在最新候选的所有方向结果均成功生成后启用。`edits.json` 记录每一步的对象 ID、操作类型、操作前后数值与可读摘要，例如“两个 Shield 框上移 3 单位”“IC 文字置于最前”；日志不依赖 path 名称是否具有语义。

## 7. 对接边界与验收

人工编辑页面只消费入口数据并输出上述文件；自动修复和 punch-out 算法继续由流水线负责。适配层将现有 punch-out 函数封装成统一入口，保证用人工确认后的 SVG，而不是旧快照，进行镂空和方向拆分。

首个真实样例应验证：

1. 参考图、正常 SVG、结构视图坐标一致；在参考图上的所选轮廓投影随移动同步。
2. 箭头／Shield 映射、Shield 框多选、数字单选符合操作员预期；重叠处可选到被遮挡文字。
3. 1 单位微调、多选移动、文字内容／字号／宽度、图层调整都可即时预览并撤销。
4. 越界提示能指出触边箭头；图层调整后正式渲染可显示原先被盖住的文字。
5. punch-out 使用最新 `edited.svg`，布局再修改后旧方向结果自动失效；最终输出数量与映射方向数量一致。
